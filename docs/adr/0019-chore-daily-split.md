# 生活事项每日分次：「三餐」= 每天 3 餐，全勾才算完成

用户需求：生活里也想有运动那样的「每天 N 次」——新增一个「三餐」事项，每天三顿饭是否都正常实现（勾满 3 餐才算完成）。现状：ADR-0016 的生活事项明确「无总量、无截止、无每日量」，`makeChoreGoal` 硬写 `count: 0, unit: ""`；ADR-0017 的分次勾选引擎（次行生成、双向镜像、三层级联）已存在，但闸门写死 `mode === "exercise"`，且 ADR-0016/0017 都明写「同日多次第一版不做」。

## Considered Options

- 形态：
  - **复用分次勾选引擎（采纳）**——一个「三餐」事项，每天出「三餐第1餐 / 第2餐 / 第3餐」三个次行，全勾才算完成；文件里看得见层级，与运动同构
  - 三个独立每日事项（早餐/午餐/晚餐）——零成本，但「三餐」这个整体不在模型里，三件事各算各的打卡率，也拿不到 1/3、2/3 的当日进度
  - 具名次行（早餐/午餐/晚餐 作为三个具名子行）——语义最贴，但现有次行正则只认 `第k{unit}`，具名子行要另开解析/幂等键/镜像一套，收益不抵成本，第一版不做
- 适用范围：**仅「每天」周期（采纳）**——次数语义就是「每天 N 次」；周/月/年事项的该做日本就是单次事件，N>1 没有自然含义，还会把挂账回扫与窗口命中口径搅乱
- 次数与单位的存储：**复用 `floor` + `unit`（采纳）**——数据模型零新增，`readPlanGoals` 本就为任意模式读 `floor`/`unit`；不新增 `dailyCount` 之类字段
- 行格式：**裸事项名（采纳）**——事项行仍是 `- [ ] 三餐 #计划/日常生活 🛫 D 📅 D`，次数只存 frontmatter；行内嵌量（`三餐 3餐`）会让历史行全部失配、改次数还得重指，且 ADR-0016 的「剥 emoji 后整行恰为事项名」识别口径必须保持
- 逾期策略：**分次事项只许「放弃」（采纳）**——「往后延 = 勾一次清全部挂账」与「次行全勾才算完成」直接相斥；补做昨天的三餐也没有意义。分次形态下表单不提供「往后延」，手写 `overdue: postpone` 一并忽略
- 入口：**向导「生活」卡与父行 ＋/☰ 弹窗都加（采纳）**——同一个字段逻辑，新建「三餐」一步到位，不必建完再改；默认事项仍为 洗碗/做卫生/买菜，不自动加三餐（两餐制/加餐因人而异，默认塞进去就是每天一条必须处理的行）

## 关键决策

- **分次判定**：`splitTickCount(floor, unit)`（可数单位且 `floor ≥ 2`，连续量单位黑名单排除）与 `SPLIT_EXCLUDED_UNITS` 下沉到 `daily.ts` 共用；`isSplitGoal` = `exercise` **或**（`chore` 且 `cycle.unit === "day"`）且分次判定成立。
- **行识别口径**：新增 `modeLineAmount(mode, floor, unit)`——生活事项恒返回 `{floor: 0, unit: ""}`（锚点行永远裸名，次数不参与识别，历史行永远可识别）；运动/复习/写作等沿用原口径。`modeLineMatch` / `isModeLineText` / `ensureSubItemMirror` 统一走它。
- **落盘**：`makeChoreGoal` 与 `saveGoal` 的 chore 分支——每天周期 + `splitTickCount > 0` 才写 `floor`/`unit`，否则 `delete goal.floor`、`unit = ""`；非分次才落 `overdue`。向导与弹窗共用同一份组装口径。
- **生成**：`ensureChoreTracking` 对该做事项统一走一次 `reconcileTickRows`——分次补 `三餐第1餐…第N餐`（unit = 目标单位），非分次 `n=0` 顺带清掉「昨天还是分次形态」的残留未勾次行（已勾是完成记录，保留）；`N` 变更只删多余未勾行，历史日期不碰。
- **勾选交互与镜像**：完全复用 ADR-0017——次行纯手动；点事项行连带勾满当日剩余次行；次行全勾 → 事项行自动勾并禁点；退勾只能退次行、镜像双向回退（`ensureSubItemMirror` 纳入 chore）。大项 `🏠 日常生活` 的三层级联（勾父 → 事项 → 次行）走既有 `toggleCheckItem`；父行仍不进 `ensureParentRollup`（ADR-0016 语义不变）。
- **统计**：全 N 勾满才算该事项当日完成。`splitTicksDone` 提供文件事实兜底（锚点镜像未回写时，次行 k=1..N 全勾仍算完成）；`computePeriodStats` 的 chore 事实收集、`computeModeGoalStats` 的 `scanChoreHit` 调用都带上 `floor/unit`，`scanChoreHit` 在锚点未勾时再认「次行全勾」。2/3 不进打卡率分子、断连击；事项行显示 `2/3` 次行进度徽标（单位随目标）。
- **改名/删除/形态转换**：改名时 `renameTickRowBase` 同步改今日次行 base（勾选态/序号/单位保留），否则旧次行失去锚点变顶层孤儿行；删除事项或陈旧挂账清理时 `choreTickLineIndices` 连块删今日次行（含已勾——失去锚点的次行会以顶层行身份污染今日打卡口径），历史文件不动。名字形如 `X第2次` 的事项名在保存入口直接拒绝。
- **刷新链顺序**：`ensureModeGoalTracking → ensureChoreTracking → ensureSubItemMirror → ensureParentRollup`——镜像要对刚生成的生活次行取事实，必须先补行再镜像。

## 取舍

- **修订 ADR-0016 的两处明写约束**：「无每日量」与「同日多次第一版不做」。前者被限定为「周/月/年事项无每日量，每天事项可有」；后者以运动同款引擎兑现。ADR-0016 原文按历史记录保留，以本 ADR 为准。
- 分次事项**放弃「往后延」**：少一种组合，换来两条规则不打架。用户若真想要「漏吃的补记」，直接改当天文件补勾（补卡约定，统计以文件事实为准）。
- 生活计划不再天然免疫 `floor`：手写 frontmatter 给周/月事项加 `floor` 会被读取，但 `isSplitGoal` 按周期挡住，视图/统计均不拆勾——字段存在但惰性，属可接受的宽容读取。
- 已勾次行在 `N` 下调或形态转换时保留（完成记录），与 ADR-0016 陈旧挂账清理同一先例；代价是文件里可能留下 `第4餐` 这种历史勾选行，界面不渲染、统计不计。
