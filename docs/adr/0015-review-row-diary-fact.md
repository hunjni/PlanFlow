# 复盘行的完成事实 = 日记「# 当日复盘」小节非空

用户需求：「今日总结」里点了「写复盘」把内容写进日记后，今日打卡的复盘行应自动勾上。此前复盘行是纯打卡计划行（无量化目标），ADR-0013 父行对账明确排除它（`live: false` 恒不自动勾）——它没有任何完成事实可言，勾与不勾全凭手点，于是「复盘打卡率」记的是「点没点勾」而不是「写没写复盘」。本决策把复盘行纳入 ADR-0011 完成事实镜像家族：**当天日记的 `# 当日复盘` 小节有非空内容 = 复盘完成**。

## Considered Options

- 完成事实口径：
  - 文件事实：日记小节非空即算，弹窗写入与直接手写同一把尺（**采纳**）——文件事实为准的全系统哲学；弹窗只是产生事实的常见途径
  - 仅弹窗路径：只有点「写复盘」写入才勾——直接在日记手写复盘不被认账，两把尺
- 取消语义：
  - 镜像（**采纳**）：事实在，手动取消是暂时态，刷新即重勾，`✋` 是唯一长期豁免——同 ADR-0013 父行
  - 单向（勾后取消不被重勾）——「事实在却未勾」成为稳态，打卡率与事实脱钩，镜像哲学破口

## 关键决策

- **`ParentRollupFact.factDone`（可选字段）**：独立完成事实通道——为真时无视目标窗口与任务池待办直接勾父行。ADR-0013 聚合通道（live + 模式子行全勾 + 待办清空）保持原样，两通道在 `parentCheckTargets` 内取其一；`✋` 豁免与幂等（已勾不入账）对两通道同样生效。
- **事实判定在视图（`ensureParentRollup`）**：读今天日记 `extractReviewSection` 非空即 factDone，仅注入名为「复盘」的计划（与「复盘按工作日统计」的名称特例同一先例；复盘的日记小节语义本就绑定这个计划名）。对账跑在刷新链既有位置，不新增对账时机。
- **即时路径复用同一对账**：写复盘弹窗写入成功 → `refreshToday()`（其链内先跑 `ensureParentRollup` 再重渲染）——不为弹窗另写勾选逻辑，弹窗写入与手写日记最终都经同一把尺落勾。
- **打卡率语义随事实走**：复盘行的打卡/连续打卡自动以「写没写复盘」为准（工作日分母口径不变，stats 既有特例）。

## 取舍

- 名称特例（`plan === "复盘"`）而非声明式配置（年度计划里加 `fact: 复盘` 之类字段）：先例已存在（工作日统计），配置面多一档对单一需求不划算；哪天出现第二个「日记事实型计划」再 generalize。
- 每次对账多一次日记 `cachedRead`：缓存读，开销可忽略。
- 复盘小节若只写了空白行不算事实（trim 后为空）——与「日记模式完成事实须亲手写下内容」同一严格度。
