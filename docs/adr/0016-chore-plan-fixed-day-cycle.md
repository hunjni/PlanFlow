# 固定日子式周期调度：日常生活计划（生活事项）

用户需求：新增一个「日常生活」计划，放洗碗、做卫生、买菜这类生活事项，周期各事项自定（每天 / 每周日 / 每周两次 / 每月三次…），逾期可选放弃或往后延。现状：插件全部调度概念都是**隐含每日**（打卡型每天惰性生成一行），代码中不存在任何周期/间隔语义（无 cron、无 every-N、无 weekday 约束，探查确认）。

## Considered Options

- 落日语义：
  - **固定日子（采纳）**——设定时选具体日子（周→星期几多选、月→几号多选、年→某月某日），只有轮到的日子事项才出现在今日清单，其余日子完全不见
  - 弹性配额（本窗口内做满 N 次即可，哪天随意）——该事项每天挂行直到做满，月/年单位会常年挂着一行未勾，与「周一到周六就没有该事项」的预期相悖
  - 每 N 天锚定起始日——用户明确选了「天/周/月/年 × 选日子」语法，N 天节奏被放弃
- 逾期处理：全局一刀切（漏了就漏了）vs **事项级策略：放弃（默认）/ 往后延（采纳双策略）**——用户点名要自行选择；往后延 = 错过后每天挂行、勾一次全部清账（家务可合并：漏了多次补做一次即追平），按次累计清账（任务池语义）对生活事项过苛，放弃
- 调度实现：
  - **惰性补写（采纳）**——仿 quota/模式行（ADR-0001/0006）：打开今日视图时按周期幂等补写「今日该做」的事项行 + 父行，绝不碰历史日期
  - 任务池预生成序列（ensureAutoTasks 摊派 🛫/📅）——周期滚动需不断补任务，且会进 filterTasksInRange 各处统计，污染面更大，放弃
- 空日大项：**整行不出现（采纳）**——不进今日进度分母、不影响连续打卡；vs 自动完成（闲日子白送完成度）。连续打卡按「当天所有顶层大项全勾」判一天（ADR-0012），多一行未勾大项即断连击，不出现是唯一安全解
- 统计口径：**周期窗口命中（采纳）**——该做日起至下次该做日前任何一天勾了都算该次命中（一条规则同时覆盖每日事项、往后延的逾期补做、放弃事项的手改补卡）；严格当日会让「往后延」变成统计惩罚模式，放弃

## 关键决策

- **数据模型**：新目标模式 `chore`（生活）挂 `PlanGoal.mode`（ADR-0006 预设层惯例，undefined=通用 的兼容口径现成）；周期 `cycle: {unit: day|week|month|year, days}`——week 用 0~6（0=周日，同 `Date.getDay`）、month 用 1~31（无此号的月份落到当月最后一天）、year 用 `[月, 日]` 二元组、day 忽略 days；逾期策略 `overdue: postpone`（缺省=放弃，只落盘非默认值）。挂「日常生活」计划（label 🏠）的 goals 下，一个事项一个 goal，`count: 0`、`unit: ""`。
- **行格式 = 事项名本身**：`- [ ] 洗碗 #计划/日常生活 🛫 D 📅 D`（buildModeCheckLine floor=0 同构）。行识别走既有 `matchesModeLine` 精确匹配（剥 emoji 后整行恰为事项名），周期徽标由视图按 frontmatter 推导渲染，不进文件。事项名不得与大项行文本（剥前缀后）同名——保存入口统一守卫（事项名 = 计划名「日常生活」直接拒绝），防父行被误判成事项行后重复补父。
- **父行 = 惰性生成 + 仅交互级联**：有事项行要写时先补父行（`🏠 日常生活`），事项行折叠其下（topLevelCheckRows 既有嵌套）；勾满事项 → 父行自动勾、勾父行 → 级联勾全部事项行，全部走 toggleCheckItem 既有级联（ADR-0003/0006 同款）。**父行不进 ensureParentRollup 对账**（ADR-0013）：生活事项无事实镜像（用户裁决 Q5a），手动取消父行是终态，刷新不得重勾。
- **逾期挂账判定 = 文件事实回扫**：postpone 事项从昨天向最近一个该做日回扫每日文件，找不到该事项已勾行 → 今天挂行（带逾期标记）；找到 → 已清账。挂账事实记入视图债务表渲染徽标（该做日恰逢旧挂账、每天周期漏了同样亮标）。只在今日文件补写，绝不回写历史。**陈旧挂账清除（唯一例外）**：策略从往后延改回放弃、或事项被删除时，今日文件中该事项的**未勾**行随之移除（共识「挂账立即消失」；已勾行是完成记录，保留）。
- **统计**：`computePeriodStats` 打卡率对生活计划改分母——done = 窗口内命中的该做次数，total = 该做次数（周/月至今口径与打卡率一致，年沿用全窗口惯例与年度卡同尺）；`computeModeGoalStats` 加 chore 分支（dueDays/hitDays = 已开始的该做次数/命中次数，streak = 连续命中的周期数）；年度卡进度 = Σ命中 ÷ Σ该做（同打卡率口径，非各目标均值——各事项该做次数不均时口径才自洽）。
- **入口**：向导新「生活」模式卡（表单：名称 + 周期下拉 + 日子选择 + 逾期策略）；保存时目标计划不存在则自动创建「日常生活」（含首个事项，避免空计划漏进每日模板推导）；大项行上 ＋/管理 按钮走独立小弹窗（增/改/删事项）。`年度计划.md` 是唯一事实源。
- **模板豁免**：生活计划不进 `buildDefaultCheckItems` 的每日模板推导（父行由惰性链生成，空日不出现靠它保证）。

## 取舍

- 往后延事项**建目标前**已越过的该做日同样算挂账（如 3 月 1 日的年度事项 11 月才建、选往后延 → 当天就挂行提醒「今年还没做」）：诚实呈现今年欠账，代价是新建即见逾期标记。
- 年度视图打卡率分母沿用全窗口惯例（含未来该做日），与年度卡其他计划的口径一致、可横向比较；周/月卡按至今口径，不含未来。
- 改名/删除事项**不追改历史**（约定同补卡）：历史日文件里的旧行原样保留、统计以文件事实为准；改名后新名从零累计。删除时今日**未勾**行随之移除（挂账无主，留着会被误认成父行）；已勾记录保留。
- 同日多次（每天 2 次）第一版不做：底层是「一行一勾」的 Tasks 格式，同日计数要为新行语法开路，收益小。
- 挂账回扫最坏读一个完整周期窗口的每日文件（年单位 ~366 个 cachedRead，与其他模式统计的逐日扫描同量级）；从昨天往回扫、命中即停，常态只读最近几天。
