# 复盘与次日计划分离：独立小节 + 视图实时侧读

用户需求：把「今日计划」里捆在一起的**复盘**与**次日计划**拆开。现状是次日计划只存在于复盘模板的最后一个子节（`## 明日计划`），「写复盘」弹窗整段写入日记 `# 当日复盘`——代码里没有任何地方单独消费它，纯属复盘正文的尾巴。痛点：两者填写时机与归属都不同（复盘向后看、次日计划向前看），次日计划不该埋在复盘正文里，且希望今晚写的计划「明天能看到」。

## Considered Options

- 次日计划落点：
  - 仍写今天的日记，但独立成节 `# 次日计划`（**采纳**）——与既有两个「写进日记」入口同一套锚点/替换语义，日记保持一条时间线
  - 写到明天的 planflow 日计划笔记——跨文件双向同步（今晚改了、明日笔记已建）要引入写回，复杂度高
  - 写到明天的日记——替 BZG 预建结构，违反「不为日记建结构」约定（ADR-0004）
- 「流到明天」的形态：
  - 视图实时侧读昨日日记（**采纳**）——零复制零同步，改了昨天的日记今天看到的就是最新的，同 BZG 只读源、复盘预填一个套路
  - 创建明日笔记时快照复制成 `## 📆 次日计划` 一节——晚上改计划后快照变旧，同步即双向写
  - Obsidian 嵌入 `![[昨日日记#次日计划]]`——只在阅读视图渲染，planflow 自己的视图解析不出嵌入，两处显示不一致
- 入口形态：两个独立按钮（**采纳**）vs 单弹窗双文本域（时机不同步的痛点没解决）vs 只拆模板不加 UI（流到明天无从谈起）

## 关键决策

- **新小节 `# 次日计划`（一级标题）**：插入锚点链 = `# 当日复盘` 节尾优先（顺序约定：… → 随笔 → 当日复盘 → 次日计划），无当日复盘退回 `# 随笔` 节尾（与复盘同一套插入规则），双锚点缺失 → no-anchor。已有小节（任意位置）→ 原位替换，一天一份，与复盘同语义。`nextDayPlanTransform` / `extractNextDayPlanSection` / `writeNextDayPlanToDiary` 与 reviewTransform 系列完全同构（小节边界 = 下一个一级标题，正文里的 `##` 子标题属本小节）。
- **入口恒指今天，展示块入口恒指昨天**：「📆 次日计划」按钮永远编辑今天日记的小节（给明天排的计划）；总结卡上方「昨日留的计划」只读块上的「去修改」永远编辑昨天日记的小节（改昨晚留给今天的）。两条线永不交叉——同一按钮指向漂移会让替换语义写错日记。写复盘入口不变。
- **视图实时侧读**：总结卡内（打卡自动三行之下、总结输入框之上）只读块，每次今日刷新（refreshToday）重读昨日日记；昨日日记不存在 / 无该节 / 内容空白 → 整块隐藏。严格只看昨日一天，不向前回溯。
- **内容形态 = 自由文本**：不做逐行任务、不投影进明日打卡清单（那会碰 ADR-0001 的幂等重建体系）；本决策只做「拆开 + 流到明天」。
- **弹窗复用 ReviewModal**：标题/提示/空文案参数化；预填 = 该日日记已有小节正文（替换语义防丢字），否则**空白**——次日计划无固定骨架，不新增模板设置项。
- **存量迁移（模板）**：默认复盘模板删 `## 明日计划` 子节；`LEGACY_REVIEW_TEMPLATE` 常量保存旧默认，加载设置时 data.json 里的模板与旧默认**逐字相同**（= 用户从未自定义）→ 静默换新默认，自定义过的一律不动。旧日记 `# 当日复盘` 里已写进去的 `## 明日计划` 内容**不迁移**（文件事实为准，无代码消费它，纯历史文本）。
- **打卡行捆绑残留清理（追补）**：用户库 `年度计划.md` 里复盘计划的 `action: 复盘+次日计划`（A股时代遗存，插件只读不写）由用户侧删除，打卡行回归「📈 复盘」；插件同步停止给复盘计划自动追加 `→ [[{date} 复盘]]` 链接（`includeReview` 恒 false）——该链接指向 v1.0 时代「写复盘建文件」流程的产物，自 ADR-0004 扩展三改写日记后目标文件从不存在，天天挂空链。手动建项的「含复盘链接」开关保留；已有日笔记的旧行按 ADR-0001 不重写（当日一行由用户手改，历史日笔记不动）。

## 取舍

- 实时侧读只在 planflow 视图可见：直接打开明天笔记的文件看不到今晚的计划（快照方案才有文件痕迹）。换取的是零同步复杂度与「永远最新」，与本项目「视图是文件事实的倒影」哲学同向。
- 按钮恒指今天的代价：早上想改「今天该干什么」，要点只读块上的「去修改」而不是那颗醒目的主按钮——指向无歧义的价值高于少一次定位。
- 总结卡底部按钮排从两枚变三枚（写入备注 / 写复盘 / 次日计划，flex 三等分）：卡片宽度下按钮文字可容纳，不再为三按钮引入折行布局。
- 写今天日记的次日计划不刷新只读块（块侧读的是昨天），写昨天（去修改）才刷新——避免无谓重读。
- 纯函数 `nextDayPlanTransform` 配单测（首写锚点随笔 / 锚点当日复盘且 `##` 子节不截断 / 重复写入幂等标题唯一 / 空行子标题保留 / 双锚点缺失 null / 既有小节原位替换不搬家 / 提取含子标题与缺失 null）。
