# 量化子项分次勾选：真嵌套次行 + 落盘镜像锚点行

用户需求：运动量化——拉伸设「每天 2 次」，拉伸行下出现「拉伸第1次 / 拉伸第2次」两条待勾行，全勾后拉伸自动勾，进而计入大项口径。现状：每日笔记与任务池全部**平铺存储**、父子关系运行时推导（最高 3 层 DOM 仅书组，且书行是派生态不落文件）；运动模式子项「每天 2 次」的现有近似是 floor=2 单行；ADR-0016 曾明确推迟同日多次（「一行一勾」格式，同日计数要为新行语法开路）。

## Considered Options

- 落盘形态：
  - **真缩进嵌套（采纳）**——次行缩进挂在子项行下，文件里直接看见层级
  - 平铺序号行（`拉伸·第1次` 与子项行同层，界面渲染成嵌套）——改动小，但用户点名要在文件里看见结构，放弃
  - 单行计数（`拉伸（实 1/2）`）——没有逐次待勾项，与需求直接相悖，放弃
- 子项行（拉伸行）自身：
  - **落盘锚点 + 事实镜像（采纳）**——真嵌套必须有真实父行作缩进锚点；其勾选态恒等于「全部次行勾满」，点它连带勾满剩余次行，全勾后禁点（书行先例），退勾只能退次行
  - 纯派生不落盘（书组式）——与真嵌套互斥（没有父行就没处缩进），放弃
  - 大项父行式单向对账（只自动勾、不自动退）——子项行唯一事实源就是次行，纯聚合却不同步回退，语义拧巴，放弃
- 数量挂级：**子项级（采纳）**——「每天 N 次」设在每个子项自己身上（拉伸 2 次、八段锦可 1 次）；大项级继承（运动=2 次 → 每个子项都出 2 个次行）语义怪，放弃
- 与 floor 的关系：**替代（采纳）**——每日目标量为**可数单位**（次/组/自定义可数单位）且 ≥2 时即分次形态，同一个设置换了呈现，无新旧并存怪态；分钟/小时/公里/千卡等连续量单位不拆（「第30分钟」不可勾），floor 照旧单行记量。次行文本带单位：「{名}第k{单位}」（拉伸第1次、拉伸第1组）——首版曾只认「次」，用户裁决「组次一样」，放宽为可数单位口径
- 逾期：**无（采纳）**——运动量不宜结转，每天照常出次行、漏了翻篇；不把 ADR-0016 的周期+挂账调度搬到运动链上

## 关键决策

- **数据模型零新增**：不加新字段、不做迁移——运动模式 goal 的 `floor`（每日目标量）为可数单位且 ≥2 即分次形态，N=1 与现状完全同构。`年度计划.md` 唯一事实源不变。
- **行格式**：次行文本「{子项名}第k{单位}」（阿拉伯序号+单位，自包含、幂等键天然互异），缩进挂在子项行下，带同款 `#计划/{计划名}` 标签与 🛫/📅 当日（buildModeCheckLine 同构）；纯手动勾、无事实镜像、无 ✋、不投影日记。子项行本身位置不变（与大项行平铺同层，界面照旧折叠渲染）。
- **解析层首次进文件层级**：每日行解析按缩进深度建父子——子项行的缩进子行 = 次行（不是模式行、不进 modeChildren 口径、不落顶层兜底）；`topLevelCheckRows` 扩为三层：大项 > 子项行 > 次行。手工文件缩进丢失的次行按独立行兜底（不入镜像聚合）。
- **生成**：ensureModeGoalTracking 对分次 goal 幂等补写子项行 + 缺的次行；N 变更当天生效——补缺行、删多余**未勾**行（已勾的是完成记录，保留；同 ADR-0016 陈旧挂账清理先例）；绝不碰历史日期。
- **勾选交互**：次行纯手动；点子项行 = 当场连带勾满当日剩余次行；次行全勾 → 子项行当场自动勾；勾满后子项行 checkbox 禁点（书行先例，ADR-0008），退勾只能退次行、镜像随之回退；勾大项级联两层下探（大项 → 子项行 → 次行）；取消一律不回退（ADR-0003）。
- **对账**：刷新链为子项行补镜像（次行全勾 → 勾；次行有退 → 回退）——唯一双向镜像行。大项父行维持 ADR-0013 单向不回退不变：大项有独立手动语义（勾优先，ADR-0012），子项行没有。
- **统计**：勾不满 N 次当天不算完成（子项行未勾即未完成，文件事实=镜像）；大项口径、连击、打卡率经既有 `topLevelCheckRows`/`computePeriodStats` 路径自动继承，无需新口径。
- **多做不记录**：第 N+1 次无处落，第一版不做超量。

## 取舍

- **修订 ADR-0016「同日多次第一版不做」**：当时以平铺为前提估算成本（「要为新行语法开路」）；本决策保住了「一行一勾」原则——每行仍是一勾，「同日计数」用「同日多行」实现，序号文本让幂等键 `plan|text` 天然不冲突。放弃的是「文件全平铺」这一内部洁癖，换来用户可直接在文件里看见并手改层级。
- **旧行重指（repoint）**：每日量/单位编辑后，既有模式行内嵌旧量（如「拉升 1次」对 floor=2）不再满足 `matchesModeLine` 的「N{unit}」要求——行被顶层化、统计失配、次行无从锚定（首个用户实测即踩）。刷新链对「[emoji ]名[ 量]」整行形的模式行原位改写到当前口径（勾选态/（实 N）后缀/标签/日期保留；次行样式行、名后带其他文本的行不碰；历史日期不改）。frontmatter 是目标量唯一事实源，行内量只是其倒影——手改行内量会被下次刷新重指回填。
- 子项行是全系统唯一落盘的**双向**镜像行（别处镜像只勾不退）：因为它纯聚合、无独立手动语义；代价是次行退勾会连带退它的勾，用户若想「保留完成记录」须整组次行一起留。
- 解析从「行数组」变「行 + 缩进父子」是全链路改动面最大的一处（解析/渲染/级联/统计/对账全要认第三层），是选平铺方案的最大理由；用户明确选择文件可见性优先，接受该成本。
